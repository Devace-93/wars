# Production runbook — wars.3m4.net

Same Hetzner box as the other 3m4 apps; the 3m4 edge Caddy terminates TLS and routes
`wars.3m4.net` to `wars-server-1:8086` over the external `edge` docker network.

## First deploy

1. DNS: `wars` A record → `46.225.62.18` at Bluehost (done 2026-10-21 by the overnight
   session unless noted otherwise in `docs/MORNING.md`).
2. On the server: `git clone https://github.com/Devace-93/wars /opt/wars && bash /opt/wars/deploy/first-deploy.sh`
   (writes `.env` with a random guest key, builds the image, starts Postgres + server).
3. Merge the 3m4 PR `deploy/wars-edge-routing` and reload Caddy (command printed by the script).
4. Check `https://wars.3m4.net/healthz` → `{"status":"ok"}` and `https://wars.3m4.net/api/civs`.
5. Cron: `5 3 * * * /opt/wars/deploy/backup.sh`.

## Deploy on push

`.github/workflows/deploy.yml` runs `first-deploy.sh` over SSH on every push to `main`
once the repository secrets `DEPLOY_HOST`, `DEPLOY_USER` and `DEPLOY_KEY` (an ed25519
private key whose public half is in the server's `authorized_keys`) exist. Until then,
deploy by re-running the script on the server.

## Environment

| Var | Production value |
|---|---|
| `DATABASE_URL` | set by compose (`postgres://wars:wars@postgres:5432/wars`) |
| `ACCOUNTS_URL` | `https://accounts.3m4.net` |
| `ACCOUNTS_INTERNAL_URL` | `http://accounts-api-1:5000` |
| `GUEST_SIGNING_KEY` | random, generated by `first-deploy.sh` |
| `PUBLIC_URL` | `https://wars.3m4.net` |

## Operations

- Logs: `docker compose --project-name wars -f deploy/docker-compose.yml -f deploy/docker-compose.prod.yml logs -f server`
- Restart: same command with `restart server`.
- Matches live in memory; a restart ends running matches (players get `MatchEnded`, their
  autosaves remain and can be resumed from the lobby as a "Saved game" source).
